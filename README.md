## Abstract

An **explainable, multi-organism, FAIR-compliant, unitig-resolution AMR biomarker
Knowledge Base** built from Whole Genome Sequencing (WGS) assemblies. The pipeline
is **alignment-free** (unitigs from a compacted de Bruijn graph — no reference
genome) and trains **out-of-core XGBoost** over millions of features, then
**reverse-translates** the most important unitigs into biology via BLAST
(CARD + NCBI) and grades every biomarker on a 7-layer evidence stack.

The point is not resistance *prediction* (already a solved ~0.93-AUC problem) but
an open, queryable KB that answers **which genomic signature drives resistance to
which antibiotic**, with full provenance.

**Current KB: 45 models · 6 ESKAPEE organisms · 14 antibiotic classes**
(*E. coli, K. pneumoniae, S. aureus, A. baumannii, P. aeruginosa, E. faecium*).
Every model is validated with **lineage-aware CV** (PopPUNK + StratifiedGroupKFold);
adding an organism is a registry entry, not a code change.

## Three core pillars

**1. Computer science / informatics**
- **Unitig features** via `unitig-caller` (compacted de Bruijn graph): built once
  per organism into a reusable store, then subset per antibiotic — no re-calling.
- **Out-of-core learning:** dynamic stratified chunking + compressed `.npz`
  sparse matrices; training streams chunks via `XGBoost QuantileDMatrix`, so
  matrices far larger than RAM are handled on commodity hardware.
- **Pinned Apptainer containers** (`amr.sif` / `amr-tools.sif` / `amr-checkm2.sif`)
  with committed conda lockfiles — every tool version is reproducible.

**2. Mathematics / statistics**
- **Bayesian HPO** with `Optuna`; `colsample_bytree` anchored to the `1/√p`
  square-root heuristic (see `METHODOLOGY.md`).
- **Lineage-aware CV** — PopPUNK strain clusters as `StratifiedGroupKFold` groups,
  so a whole lineage stays on one side of the split. This is the *reported* metric
  (`models.auc_mean_seeds`); the single-split AUC is kept only for contrast.
- **Unbiased thresholding** (threshold from the *training* distribution), bootstrap
  95% CIs, CPSS stability selection with a PFER bound, MDA + label-permutation
  nulls, and **pyseer LMM** for population-structure-corrected significance.

**3. Biology**
- **Reference-free discovery:** top unitigs are BLASTed against **CARD** (local)
  and **NCBI nt** (remote) directly via `blastn` subprocesses, then graded into
  confirmed / candidate / weak tiers.
- **Evidence-weighted tiers** (`unitig_evidence_tier`): a biomarker that is
  CPSS-stable *and* pyseer-significant *and* has no CARD hit is flagged
  **`strong_novel`** — the KB's actual contribution.

### Data layout (organism-scoped)

Paths are resolved through `scripts/lib/config.py:resolve_path()` from the
`{organism}` templates in `config.yaml`:

- `data/raw/{organism}/genomes/` — immutable `.fna` assemblies
- `data/external/{organism}/metadata/amr_phenotypes.csv` — phenotype labels
- `data/external/blast_db/card_nt/` — CARD BLAST DB (shared)
- `data/processed/{organism}/lineage/` — PopPUNK clusters (`poppunk_clusters.csv`) + sketch DB
- `data/processed/{organism}/unitig_all/` — organism-level unitig store (built once)
- `data/processed/{organism}/{antibiotic}/matrix/` — `.npz` chunks, `y_*.csv`
- `models/{organism}/{antibiotic}/` — model + `manifest.json`
- `results/{organism}/{antibiotic}/` — plots + metric CSVs *(generated)*
- `runs/{organism}/{antibiotic}/{run_id}/` — run metadata + metrics *(generated)*

> **Generated outputs** (`results/`, `logs/`, `runs/`, models, `.npz`, large
> `features.txt`) are **not version-controlled** — they are reproduced by
> running the pipeline.

## Pipeline workflow

**Per-organism, once:** `00a` → `00` → `02c` → `02d/M15` → `03u --build-db`
**Per antibiotic, strictly sequential:** `03u` → `04-07b` → `07-09` → `10-13b` → `14` → `populate`

| Step | Script | Description |
| :--- | :--- | :--- |
| 00a | `00a_download_bvbrc.py` | BV-BRC AMR phenotypes + assemblies (drops *computational* rows) |
| 00 | `00_prepare_metadata.py` | Long → wide binary phenotype matrix (registry-canonical drug names) |
| 01 | `01_data_validation.py` / `01b_…` | Validate metadata, class balance, EDA plots |
| **02c** | `02c_lineage_poppunk.py` | **PopPUNK strain clusters → the CV groups** (`poppunk_clusters.csv`) |
| **02d** | `02d_genome_qc.py` | **CheckM2 + QUAST genome QC** → `global_qc_outliers.csv` (excluded by 03u) |
| 03u | `03u_unitig_matrix.py` | Unitig presence/absence matrix; `--build-db` builds the organism store once, per-antibiotic runs subset it |
| 04 | `04_optimization.py` | Optuna Bayesian HPO → `config_{antibiotic}.yaml` + run metadata |
| 05 | `05_model_training.py` | XGBoost over a streaming `QuantileDMatrix` → model + `manifest.json` |
| 06 | `06_evaluation.py` | Metrics, ROC/PR, calibration, bootstrap CIs |
| 07b | `07b_feature_stability.py` | **Lineage-aware CV** (`auc_mean_seeds`, `cv_method`) + feature stability |
| 07 | `07_explainability.py` | Gain-based top unitigs ∪ stable set → CSV + FASTA |
| 08 | `08_blast_annotation.py` | `blastn` vs CARD (local) + NCBI nt (remote), via subprocess |
| 09 | `09_biological_summary.py` | Confidence-tiered biological report + KB candidates |
| 10–11 | `10_…` / `11_…` | Background frequency; CARD variant-model SNP allele check |
| 12–12b | `12_…` / `12b_…` | MDA permutation importance; label-permutation null |
| 13–13b | `13_…` / `13b_…` | CPSS stability selection (PFER) + TreeSHAP; CARD-annotate stable set |
| 14 | `14_pyseer_lmm.py` | pyseer LMM — population-structure-corrected significance |
| — | `populate_database.py` | Load model + all evidence → `results/kb/amrk.db` (grades `unitig_evidence_tier`) |

> Order matters: `10` reads `09`'s KB candidates and `14` reads `13`'s stable set,
> so the chain is **sequential per antibiotic** — different (organism, antibiotic)
> pairs run in parallel via the env-parametric `slurm/` scripts.

## Results — 45 models, 6 ESKAPEE organisms

All numbers are **lineage-aware CV** ROC-AUC (`models.auc_mean_seeds`; PopPUNK +
StratifiedGroupKFold). Every one of the 45 models reports
`cv_method = lineage_group_kfold_5fold` — no fallbacks.

| Organism | Models | Mean lineage-CV AUC |
| :--- | ---: | ---: |
| *E. faecium* | 6 | 0.933 |
| *E. coli* | 8 | 0.917 |
| *S. aureus* | 8 | 0.836 |
| *K. pneumoniae* | 11 | 0.834 |
| *A. baumannii* | 8 | 0.759 |
| *P. aeruginosa* | 4 | 0.755 |
| **Panel** | **45** | **0.842** (0.429–0.975) |

**Biology recovered by the top unitigs** (100% CARD identity): *mecA* for MRSA
(S. aureus cefoxitin/oxacillin), the *vanA* cluster for VRE (E. faecium
vancomycin/teicoplanin), *CTX-M*/*TEM* for E. coli cephalosporins, *KPC*/*NDM* for
K. pneumoniae carbapenems, *OXA* carbapenemases for A. baumannii. Models with **no**
CARD-confirmed hit are exactly the mutation-driven/intrinsic phenotypes
(*gyrA*/*parC*, *pbp5*, porin loss) that a nucleotide gene database cannot capture —
those are handled by the SNP (11) and pyseer (14) layers.

**Why lineage-aware CV matters — the panel's sharpest example.** *A. baumannii*
ceftazidime scores **0.985 on a single random split but 0.429 under lineage-CV**
(mean pairwise Jaccard of selected features across folds: 0.04). The model memorises
a clone-specific pattern and collapses when that clone is held out. A random split
would have published a near-perfect headline for a phenotype the features cannot
actually generalise to.

**Evidence tiers across the KB:** confirmed 349 · candidate 947 · weak 1915 ·
none 337 · **`strong_novel` 23** (CPSS-stable + pyseer-significant + no CARD hit).

Validation stack: lineage-aware CV, CPSS stability selection + PFER bound,
MDA + label-permutation nulls, pyseer LMM, CARD variant-model SNP check, genome QC
(CheckM2 + QUAST), and AMRFinderPlus/ResFinder external concordance.
Remaining: Zenodo DOI, MIC sensitivity analysis, geographic hold-out.

## Installation

**Python:** 3.10+. External tools (unitig-caller, PopPUNK, BLAST+, pyseer, CheckM2)
are not pip-installable — use the containers (reproducible) or conda.

### Option A — Apptainer containers (what the published run used)

Three pinned images, each with a committed lockfile. The split is **deliberate**:
`pyseer`/`ResFinder`/`AMRFinderPlus` resolve to Python 3.8 while PopPUNK and the ML
stack need 3.12, so a single image is impossible — the steps exchange plain text.

```bash
apptainer build amr.sif          containers/amr.def          # 00a-13b + 02c PopPUNK (py3.12)
apptainer build amr-tools.sif    containers/amr-tools.def    # 14 pyseer, M13 AMRFinder/ResFinder (py3.8)
apptainer build amr-checkm2.sif  containers/amr-checkm2.def  # 02d/M15 genome QC
apptainer exec --no-home amr.sif python scripts/03u_unitig_matrix.py --help
```

### Option B — conda

```bash
conda env create -f environment.yml
conda activate amr-prediction
```

### Option C — pip (Python deps only; install tools separately)

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Then install the external tools yourself: `unitig-caller` ≥1.3, `PopPUNK` ≥2.7,
BLAST+ ≥2.16, `pyseer` ≥1.3, CheckM2 ≥1.1. Tools are found on `PATH`.

## Quickstart

The target comes from the environment (`AMR_ORGANISM` / `AMR_ANTIBIOTIC`), falling
back to `config.yaml`. Set it once and the whole chain follows:

```bash
export AMR_ORGANISM=ecoli AMR_ANTIBIOTIC=cefotaxime AMR_FEATURE_REPR=unitig

# --- per organism, once ---
python scripts/00a_download_bvbrc.py --organism $AMR_ORGANISM   # BV-BRC phenotypes + assemblies
python scripts/00_prepare_metadata.py --organism $AMR_ORGANISM  # binary phenotype matrix
python scripts/02c_lineage_poppunk.py --organism $AMR_ORGANISM  # PopPUNK lineages = the CV groups
python scripts/02d_genome_qc.py --mode prep --organism $AMR_ORGANISM   # then CheckM2 + QUAST, then:
python scripts/02d_genome_qc.py --mode post --organism $AMR_ORGANISM   # -> global_qc_outliers.csv
python scripts/03u_unitig_matrix.py --build-db --organism $AMR_ORGANISM # unitig store (once)

# --- per antibiotic ---
python scripts/01_data_validation.py
python scripts/03u_unitig_matrix.py       # subsets the store -> matrix_unitig/ + unitigs.rtab
python scripts/04_optimization.py
python scripts/05_model_training.py
python scripts/06_evaluation.py
python scripts/07b_feature_stability.py   # lineage-aware CV + stability (run before 07)
python scripts/07_explainability.py       # gain top-N ∪ stable set -> CSV + FASTA
python scripts/08_blast_annotation.py     # needs BLAST+ and the local CARD DB
python scripts/09_biological_summary.py   # tiered report; set ncbi.entrez_email or AMR_ENTREZ_EMAIL
python scripts/10_kmer_background_frequency.py  # resistant-vs-susceptible discriminativeness
python scripts/11_variant_snp_check.py    # CARD variant-model SNP allele check (optional)
python scripts/12_permutation_test.py     # M9: MDA permutation importance (+ BH-FDR)
python scripts/12b_label_permutation_test.py  # M9: label-permutation null (model significance)
python scripts/13_stability_selection.py  # M4: CPSS stability selection (PFER bound) + TreeSHAP
python scripts/13b_stable_annotation.py   # M4: CARD-annotate the stable set (tier + ARO)
python scripts/14_pyseer_lmm.py --mode prep   # then pyseer CLIs (amr-tools.sif), then --mode post
python scripts/populate_database.py --organism $AMR_ORGANISM --antibiotic $AMR_ANTIBIOTIC   # -> results/kb/amrk.db (schema 0.7.1)
streamlit run scripts/kb_app.py           # local queryable KB explorer (pip install streamlit pandas)
uvicorn scripts.kb_api:app                # REST API (S8/S9): /api/v1/{kmers,kmers/{seq},overlap,stats,metadata} + /docs
```

**Querying the KB via the REST API** (`scripts/kb_api.py`, FastAPI):

```bash
pip install fastapi uvicorn
AMR_KB_DB=results/kb/amrk.db uvicorn scripts.kb_api:app   # http://localhost:8000/docs
# GET /api/v1/kmers?antibiotic=cefotaxime&tier=confirmed&stable_only=true
# GET /api/v1/kmers/{sequence}     GET /api/v1/overlap?ab1=ampicillin&ab2=cefotaxime
# GET /api/v1/stats                GET /api/v1/metadata   (FAIR: schema ver, DOI, license)
```

> **Feature unit = unitig** (compacted de Bruijn graph; see `METHODOLOGY.md`). The
> pipeline runs per antibiotic (`AMR_ANTIBIOTIC`, or `project.target_antibiotic` in
> `config.yaml`); the KB is unified across organisms and antibiotics. Each run is
> reproducible — `pipeline_runs` stamps the git commit, seed, config hash and every
> tool version.

See `QUICKSTART.md` for prerequisites, HPC notes and expected outputs.

## Running the full panel on HPC (SLURM)

The `slurm/` scripts are **env-parametric** — one script serves every
(organism, antibiotic) pair, so the 45-model panel is a submit loop:

```bash
sbatch --export=ALL,AMR_ORGANISM=kpneumoniae,AMR_ANTIBIOTIC=meropenem,AMR_FEATURE_REPR=unitig \
       slurm/run_03uml_env.slurm        # 03u -> 04 -> 05 -> 06 -> 07b
```

| Script | Covers |
| :--- | :--- |
| `run_m15_qc_env.slurm` | 02d/M15 CheckM2 + QUAST genome QC (per organism) |
| `run_03u_build_env.slurm` | `03u --build-db` unitig store (per organism, once) |
| `run_03uml_env.slurm` | 03u subset + 04–07b (the ML half) |
| `faz2a_all.sh` / `faz2a_retry.sh` | 07→08→09 driver (NCBI is serial; self-healing retry) |
| `run_03ubio_env.slurm` / `run_bio_env.slurm` | 10–13b biological validation |
| `run_pyseer_env.slurm` | 14 pyseer LMM (spans `amr.sif` + `amr-tools.sif`) |

Chain them with `--dependency=afterok:<jobid>`; `populate_database.py` runs last and
**once** per model (it is not idempotent after child rows exist).

## Orchestration & developer workflow

```bash
make help                          # list all targets
make dev-install                   # install the QA toolchain (ruff/mypy/pre-commit) + pre-commit hooks
make lint                          # ruff
make test                          # unit + smoke
python scripts/run_pipeline.py --list                         # show the step plan
python scripts/run_pipeline.py --organism ecoli --antibiotic ampicillin   # run the analysis core 01->10
make tables                        # tidy thesis tables from the KB (+ H3, CV comparison, novel context)
make figures                       # every thesis figure (runs `make tables` first)
```

Build the thesis artefacts through `make`, not by calling the figure scripts in a
loop: each takes a different set of flags (`kb_figures_model.py` has no `--db`), so a
loop that passes one set to all of them makes argparse exit while still looking like it
succeeded. Override the paths when the results live elsewhere, e.g. on the HPC:

```bash
make figures KB=$AMR_WORK/results/kb/amrk.db RESULTS=$AMR_WORK/results \
             TABLES=$AMR_WORK/results/tables FIGURES=$AMR_WORK/results/figures \
             PYTHON="apptainer exec --no-home $AMR_WORK/containers/amr.sif /opt/amr-env/bin/python"
```

CI (GitHub Actions, `.github/workflows/ci.yml`) runs ruff + the unit/smoke suite on Python 3.10–3.12.

## Reproducibility & data

The repository tracks **only code, configuration, container definitions, lockfiles
and docs**. All datasets, unitig matrices, models, results and run metadata are
*generated* by running the pipeline (see `QUICKSTART.md`). The CARD BLAST DB is
**not** tracked — build it locally (`makeblastdb`) as step 08's error message
explains; 08 hard-fails when it is missing rather than silently producing a KB with
an empty biology layer.

Every run records its git commit, seed, config hash and the versions of the tools
that actually shaped the result — `unitig-caller`, `PopPUNK`, **graph-tool**
(PopPUNK's backend re-solves the clustering, so pinning PopPUNK alone is not
enough), BLAST, pyseer and the CARD snapshot — in `pipeline_runs` and
`runs/.../run_metadata.json`. Genome data comes from
[BV-BRC](https://www.bv-brc.org); resistance annotations from
[CARD](https://card.mcmaster.ca).

## Data availability & KB versioning (FAIR)

The **AMRK-DB knowledge base** (`results/kb/amrk.db` — one unified multi-organism
database; `pipeline_runs.organism` distinguishes rows) is released under
**CC-BY-4.0** (distinct from the MIT-licensed code) and versioned with a semantic
`kb_schema_version` (currently **0.7.1**, stamped in the `kb_metadata` table).
Every KB record links to a `pipeline_runs` row carrying the git commit, random
seed, config hash and CARD version, so any biomarker is reproducible.

Each release is archived on **Zenodo** with a persistent DOI (concept DOI resolves
to the latest version; each version also gets its own DOI). The DOI is stored in
`kb_metadata.zenodo_doi` and mirrored in [`CITATION.cff`](CITATION.cff) /
[`.zenodo.json`](.zenodo.json).

> **Zenodo DOI:** [`10.5281/zenodo.21789464`](https://doi.org/10.5281/zenodo.21789464) — the archived knowledge base
> (KB + evidence tables + figures + run metadata). The concept DOI always resolves to
> the latest version; see [`docs/RELEASE_ZENODO.md`](docs/RELEASE_ZENODO.md).

Raw genome assemblies come from [BV-BRC](https://www.bv-brc.org); resistance
gene annotations from [CARD](https://card.mcmaster.ca) (the exact snapshot is
recorded per run in `pipeline_runs.card_version`). The pipeline
regenerates the unitig matrices from the BV-BRC assemblies, so the FAIR deposit
ships the KB + evidence tables + run metadata rather than the large raw matrices.
